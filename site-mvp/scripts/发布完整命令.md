下面给你一份“在生产服务器上从 0 到上线”的完整命令清单，已经按你现在的 GHCR 镜像模式整理好了。  
默认假设服务器是 Ubuntu 22.04，项目目录用 /opt/chemical/app/site-mvp。

## 仅上传 deploy + sql 的部署方式（完全不依赖 git）

如果你上传的是部署包目录（例如 /opt/chemical/server-deploy），且目录内包含 deploy/、sql/、.env，则按下面执行：

    cd /opt/chemical/server-deploy
    sed -i 's/\r$//' .env
    sed -i 's/\r$//' deploy/scripts/*.sh
    chmod 600 .env
    chmod +x deploy/scripts/*.sh
    set -a; source .env; set +a
    APP_DIR="$PWD" bash deploy/scripts/deploy.sh

要求：
- .env 中设置 ENABLE_GIT_SYNC=0（默认即为 0）。
- deploy/scripts/deploy.sh、deploy/docker-compose.prod.yml、deploy/nginx/site.conf.template、sql/ 目录必须齐全。
- 首次签证书仍使用 issue-certificate.sh，路径不变：deploy/scripts/issue-certificate.sh。




先说明一次：
- 下面分成 首次上线 和 日常发布 两套命令
- 你项目里会用到这些文件：bootstrap-server.sh、issue-certificate.sh、deploy.sh、docker-compose.prod.yml
    - bootstrap-server.sh：服务器一次性初始化脚本，负责安装/校验 Docker 相关环境、创建部署目录与基础安全设置。
    - issue-certificate.sh：首次签发 Let's Encrypt 证书脚本，用于为域名生成 HTTPS 证书（一般只在首发和证书丢失时使用）。

1. 首次上线（第一次在新机器执行）

1. 登录服务器并准备部署目录（root）
    
    sudo -i
    mkdir -p /opt/chemical
    cd /opt/chemical

2. 拉代码
    
    git clone https://github.com/snowduckhaha/Chemical.git app
    cd /opt/chemical/app/site-mvp

3. 给脚本执行权限
    
    chmod +x deploy/scripts/*.sh

4. 服务器初始化（只需一次）
    
    export DEPLOY_USER=deploy
    export DEPLOY_DIR=/opt/chemical
    export SSH_PUBLIC_KEY='替换成你的SSH公钥'
    bash deploy/scripts/bootstrap-server.sh

5. 切换到 deploy 用户
    
    su - deploy
    cd /opt/chemical/app/site-mvp

6. 准备生产环境变量
    
    cp deploy/.env.production.example .env
    chmod 600 .env
    nano .env

7. 在 .env 至少填写这些项（示例值按你实际改）
    
    SITE_DOMAIN=your-domain.com
    BACKEND_IMAGE=ghcr.io/snowduckhaha/chemical-backend:latest
    FRONTEND_IMAGE=ghcr.io/snowduckhaha/chemical-frontend:latest
    GHCR_USERNAME=你的GitHub用户名
    GHCR_TOKEN=你的GitHub_PAT
    UPLOADS_DIR=/opt/chemical/uploads
    MYSQL_DATA_DIR=/opt/chemical/mysql-data
    MYSQL_ROOT_PASSWORD=高强度随机密码
    MYSQL_PASSWORD=另一组高强度随机密码

8. 首次签发证书（域名 A 记录已指向该服务器）
    
    sudo deploy/scripts/issue-certificate.sh your-domain.com ops@your-domain.com

9. 执行首发部署
    
    cd /opt/chemical/app/site-mvp
    set -a; source .env; set +a
    APP_DIR="$PWD" deploy/scripts/deploy.sh

10. 上线验证
    
    docker compose --env-file .env -f deploy/docker-compose.prod.yml ps
    curl -I https://your-domain.com/
    curl --fail https://your-domain.com/api/v1/health
    curl -I https://your-domain.com/zh

2. 日常发布（以后每次发版）

1. 本地先推新镜像到 GHCR（你已在做）
- backend 和 frontend 推新 tag 或 latest

2. 服务器执行发布
    
    cd /opt/chemical/app/site-mvp
    set -a; source .env; set +a
    APP_DIR="$PWD" deploy/scripts/deploy.sh

3. 发布后验证
    
    docker compose --env-file .env -f deploy/docker-compose.prod.yml ps
    curl --fail https://your-domain.com/api/v1/health

3. 证书续期和备份（建议配置定时任务）

1. 打开 crontab
    
    crontab -e

2. 加入这两行
    
    15 3 * * * cd /opt/chemical/app/site-mvp && deploy/scripts/backup-local.sh >> /opt/chemical/backups/backup.log 2>&1
    45 3 * * * cd /opt/chemical/app/site-mvp && sudo deploy/scripts/renew-certificate.sh >> /opt/chemical/backups/cert-renew.log 2>&1

4. 常用排障命令（上线失败时）

1. 看容器状态
    
    cd /opt/chemical/app/site-mvp
    docker compose --env-file .env -f deploy/docker-compose.prod.yml ps -a

2. 看网关日志
    
    docker compose --env-file .env -f deploy/docker-compose.prod.yml logs -f gateway

3. 看后端日志
    
    docker compose --env-file .env -f deploy/docker-compose.prod.yml logs -f backend

4. 看 MySQL 日志
    
    docker compose --env-file .env -f deploy/docker-compose.prod.yml logs -f mysql

5. 手工测试 GHCR 拉取权限（怀疑 token 失效时）
    
    cat .env | grep GHCR_
    docker login ghcr.io -u 你的GitHub用户名
    docker pull ghcr.io/snowduckhaha/chemical-backend:latest
    docker pull ghcr.io/snowduckhaha/chemical-frontend:latest

5. 一条命令版（你已经配置好 .env 且证书也签过）

以后你每次发版，只要执行这一组就行：
    
    cd /opt/chemical/app/site-mvp
    set -a; source .env; set +a
    APP_DIR="$PWD" deploy/scripts/deploy.sh
    curl --fail https://your-domain.com/api/v1/health

如果你现在是“服务器直接拉 GHCR 镜像上线”，deploy 目录里可以这样分：

必须要有（生产运行必需）
- deploy/docker-compose.prod.yml
- deploy/nginx/site.conf.template
- deploy/.env.production.example  
  说明：用于生成服务器上的 .env
- deploy/scripts/deploy.sh

首次上线强烈建议有（一次性/初始化）
- deploy/scripts/bootstrap-server.sh
    说明：用于新机器一次性初始化（系统依赖、部署目录、基础安全策略）。你的机器若已完成这些工作，可跳过执行。
- deploy/scripts/issue-certificate.sh
    说明：用于首次申请域名证书，确保 Nginx 可以启用 HTTPS 对外服务。

长期运维建议有（日常维护）
- deploy/scripts/renew-certificate.sh
- deploy/scripts/backup-local.sh

当前 GHCR 拉取模式下不是运行必需
- deploy/Dockerfile.backend
- deploy/Dockerfile.frontend  
  说明：它们用于构建并推送 GHCR 镜像（CI 或本地构建阶段），服务器运行时不需要用到。
- deploy/nginx/frontend.conf  
  说明：当前生产 compose 挂载的是 site.conf.template，这个文件不是当前链路必需。
- deploy/DEPLOYMENT_TENCENT_GLOBAL.md  
  说明：文档，不参与运行。

补充一条关键点：  
你的 deploy/scripts/deploy.sh 还依赖 sql 目录里的 SQL 文件初始化数据库，所以上线时必须保留整个 sql 目录。
