下面给你一份"在生产服务器上从 0 到上线"的完整命令清单，已经按你现在的 GHCR 镜像模式整理好了。  
默认假设服务器是 Ubuntu 22.04，项目目录用 /opt/chemical/app/site-mvp。

## 架构说明

- **HTTPS 由 CDN 处理**：Nginx 只监听 80 端口（HTTP），不需要配置 443 或 Let's Encrypt 证书。
- **镜像来源**：服务器从 GHCR 拉取预构建镜像，不在服务器上构建。
- **部署脚本分两个**：
  - `first-deploy.sh`：首次发布，包含数据库初始化（建表 + 种子数据）
  - `deploy.sh`：日常发布，只拉镜像 + 重启服务，不动数据库

## 涉及的文件

| 脚本 | 用途 |
|------|------|
| deploy/scripts/bootstrap-server.sh | 服务器一次性初始化（安装 Docker、创建用户、防火墙等） |
| deploy/scripts/first-deploy.sh | **首次发布**：拉镜像 + 初始化数据库 + 启动全部服务 |
| deploy/scripts/deploy.sh | **日常发布**：拉镜像 + 重启服务（不碰数据库） |
| deploy/scripts/backup-local.sh | 数据库和上传文件备份 |
| deploy/docker-compose.prod.yml | 生产容器编排 |
| deploy/nginx/site.conf.template | Nginx 配置模板（仅 HTTP 80） |
| deploy/.env.production.example | 环境变量模板 |
| sql/ 目录 | 数据库初始化脚本（仅首次发布需要） |

## 1. 首次上线（第一次在新机器执行）

### 1.1 登录服务器并准备部署目录

```bash
sudo -i
mkdir -p /opt/chemical
cd /opt/chemical
```

### 1.2 拉代码

```bash
git clone https://github.com/snowduckhaha/Chemical.git app
cd /opt/chemical/app/site-mvp
```

### 1.3 给脚本执行权限

```bash
chmod +x deploy/scripts/*.sh
```

### 1.4 服务器初始化（只需一次）

```bash
export DEPLOY_USER=deploy
export DEPLOY_DIR=/opt/chemical
export SSH_PUBLIC_KEY='替换成你的SSH公钥'
bash deploy/scripts/bootstrap-server.sh
```

### 1.5 切换到 deploy 用户

```bash
su - deploy
cd /opt/chemical/app/site-mvp
```

### 1.6 准备生产环境变量

```bash
cp deploy/.env.production.example .env
chmod 600 .env
nano .env
```

### 1.7 在 .env 至少填写这些项

```
SITE_DOMAIN=your-domain.com
BACKEND_IMAGE=ghcr.io/snowduckhaha/chemical-backend:latest
FRONTEND_IMAGE=ghcr.io/snowduckhaha/chemical-frontend:latest
GHCR_USERNAME=你的GitHub用户名
GHCR_TOKEN=你的GitHub_PAT
UPLOADS_DIR=/opt/chemical/uploads
MYSQL_DATA_DIR=/opt/chemical/mysql-data
MYSQL_ROOT_PASSWORD=高强度随机密码
MYSQL_PASSWORD=另一组高强度随机密码
```

### 1.8 执行首次发布（含数据库初始化）

```bash
cd /opt/chemical/app/site-mvp
set -a; source .env; set +a
APP_DIR="$PWD" deploy/scripts/first-deploy.sh
```

### 1.9 上线验证

```bash
docker compose --env-file .env -f deploy/docker-compose.prod.yml ps
curl -I http://your-domain.com/
curl --fail http://your-domain.com/api/v1/health
curl -I http://your-domain.com/zh
```

## 2. 日常发布（以后每次发版）

### 2.1 本地先推新镜像到 GHCR

- backend 和 frontend 推新 tag 或 latest

### 2.2 服务器执行发布

```bash
sudo -i
cd /opt/chemical/app/site-mvp
set -a; source .env; set +a
APP_DIR="$PWD" deploy/scripts/deploy.sh
```

### 2.3 发布后验证

```bash
docker compose --env-file .env -f deploy/docker-compose.prod.yml ps
curl --fail http://your-domain.com/api/v1/health
```

## 4. 常用排障命令（上线失败时）

### 4.1 看容器状态

```bash
cd /opt/chemical/app/site-mvp
docker compose --env-file .env -f deploy/docker-compose.prod.yml ps -a
```

### 4.2 看网关日志

```bash
docker compose --env-file .env -f deploy/docker-compose.prod.yml logs -f gateway
```

### 4.3 看后端日志

```bash
docker compose --env-file .env -f deploy/docker-compose.prod.yml logs -f backend
```

### 4.4 看 MySQL 日志

```bash
docker compose --env-file .env -f deploy/docker-compose.prod.yml logs -f mysql
```

### 4.5 手工测试 GHCR 拉取权限（怀疑 token 失效时）

```bash
cat .env | grep GHCR_
docker login ghcr.io -u 你的GitHub用户名
docker pull ghcr.io/snowduckhaha/chemical-backend:latest
docker pull ghcr.io/snowduckhaha/chemical-frontend:latest
```

## 6. 仅上传 deploy + sql 的部署方式（完全不依赖 git）

如果你上传的是部署包目录（例如 /opt/chemical/server-deploy），且目录内包含 deploy/、sql/、.env，则按下面执行：

**首次发布：**

```bash
cd /opt/chemical/server-deploy
sed -i 's/\r$//' .env
sed -i 's/\r$//' deploy/scripts/*.sh
chmod 600 .env
chmod +x deploy/scripts/*.sh
set -a; source .env; set +a
APP_DIR="$PWD" bash deploy/scripts/first-deploy.sh
```

**日常发布：**

```bash
cd /opt/chemical/server-deploy
sed -i 's/\r$//' .env
sed -i 's/\r$//' deploy/scripts/*.sh
chmod 600 .env
chmod +x deploy/scripts/*.sh
set -a; source .env; set +a
APP_DIR="$PWD" bash deploy/scripts/deploy.sh
```

要求：
- .env 中设置 ENABLE_GIT_SYNC=0（默认即为 0）。
- 首次发布：deploy/scripts/first-deploy.sh、deploy/docker-compose.prod.yml、deploy/nginx/site.conf.template、sql/ 目录必须齐全。
- 日常发布：sql/ 目录不是必需的（deploy.sh 不执行 SQL）。

## 7. 文件清单说明

**必须要有（生产运行必需）**
- deploy/docker-compose.prod.yml
- deploy/nginx/site.conf.template
- deploy/.env.production.example（用于生成服务器上的 .env）
- deploy/scripts/deploy.sh
- deploy/scripts/first-deploy.sh

**首次上线需要（一次性）**
- deploy/scripts/bootstrap-server.sh — 新机器初始化
- sql/ 目录 — 数据库建表和种子数据（仅 first-deploy.sh 使用）

**长期运维建议有**
- deploy/scripts/backup-local.sh

**服务器上不需要**
- deploy/Dockerfile.backend — 用于本地/CI 构建镜像推送到 GHCR
- deploy/Dockerfile.frontend — 同上
- deploy/nginx/frontend.conf — 当前生产用的是 site.conf.template
- deploy/scripts/issue-certificate.sh — 不再需要（HTTPS 由 CDN 处理）
- deploy/scripts/renew-certificate.sh — 不再需要（HTTPS 由 CDN 处理）
- deploy/DEPLOYMENT_TENCENT_GLOBAL.md — 文档，不参与运行
